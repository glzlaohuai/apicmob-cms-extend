# CMS 功能扩展

## 安装

1. 安装 Tampermonkey 后，打开[整合脚本安装地址](https://raw.githubusercontent.com/glzlaohuai/apicmob-cms-extend/master/cms-extensions.user.js)，在 Tampermonkey 中确认安装。
2. 停用原有的动态报表返回按钮、模组套用模板和 SDK 广告位批量上传三个独立脚本，避免重复运行。
3. 刷新 CMS，点击右下角的设置图标，在独立标签页中配置功能开关。

设置页地址：<https://cms.apicmob.com/?apicmob-cms-settings=1>。需要先安装整合脚本。

## 更新

脚本通过固定的 GitHub Raw 地址提供安装和更新，`@updateURL` 与 `@downloadURL` 已写入安装包。

- 用户可以在 Tampermonkey 中手动检查更新，也可以在启用更新检查后按其设置定期检查；是否自动安装或需要确认由 Tampermonkey 设置决定。更新完成后刷新 CMS 页面。
- 原来通过本地文件或复制代码安装的用户，需要先通过上面的安装地址覆盖安装一次，以配置托管更新地址。保持原有脚本名称和命名空间，避免重复安装。
- 功能开关仍保存在当前浏览器的 CMS 站点存储中，更新脚本不会重置这些设置。

## 功能开关

| 功能 | 生效位置 |
| --- | --- |
| 动态报表返回按钮 | 动态报表详情页 |
| 模组配置套用模板 | 模组配置编辑页，支持独立模组、H5 链接和 SDK 配置 |
| SDK 广告位批量上传 | SSP 媒体详情的 SDK 广告位列表，需要先选择应用 |
| SDK 配置总览布局 | SDK 配置总览页，将“正式模式版本活跃度最小值”及修改、保存按钮从 App ID 信息区移出，在信息区下方、配置表上方独立展示 |
| 集成渠道控量展示 | 集成概览页，直接按渠道展示模组控量开关状态 |
| 集成模组渠道命名 | 集成详情添加模组时，默认名称自动追加渠道名后缀 |

所有功能默认开启。设置自动保存在当前浏览器的 CMS 站点存储中，并同步到同一浏览器配置下已打开的 CMS 标签页。不同浏览器或浏览器配置之间不共享设置。

SDK 广告位批量上传在名称前缀下方提供独立的“名称包含前缀”和“名称包含位置类型”开关，分别默认开启、关闭，并记住当前浏览器的选择。前缀开启且留空时使用应用名称；关闭时禁用前缀输入框并保留输入值，名称中不再添加前缀或应用名称。两个开关都开启时名称为 `前缀-Excel名称-位置类型-价格或bidding`，例如 `App-Home-banner-2.5`；都关闭时为 `Excel名称-价格或bidding`。预览和最终创建使用相同命名规则。每条广告位完成创建、结算配置及启用后，会自动执行一次同步；同步失败会标记为部分完成，并保留广告位 ID。

批量上传模板的列依次为“名称、广告类型、结算模式、固定价格、最低价格、最高价格、尺寸”。“尺寸”可留空，非空时填写 `宽x高`，例如 `320x50`、`1080×1920`，也支持 `X` 和 `*` 分隔符，宽高必须是正整数。填写时优先使用该行尺寸，留空时使用对应广告类型的默认尺寸；仍兼容不含尺寸列的旧六列模板。

在批量上传窗口展开“默认尺寸（宽 × 高）”，可分别修改 banner、interstitial、incentivized、native、splash 的宽高，点击“保存默认尺寸”后更新预览并持久化到当前浏览器的 CMS 站点存储，供后续批次及其他应用使用。初始值为 banner `320×50`，其余类型 `9×16`，可点击“恢复初始尺寸”恢复并保存。有未保存的尺寸修改时无法开始创建；保存失败会显示原因。Excel 内已填写的尺寸不会被默认配置覆盖，预览和最终创建使用相同尺寸。

批量创建结束后，自动下载 `原文件名-创建结果.xlsx`，在原工作表对应行回填“位置ID、位置内部ID、集成ID、DSP联盟位置ID、创建状态、处理结果”。“位置ID”是页面展示的广告位编号，“位置内部ID”是创建接口返回的记录 ID；ID 以文本写入。保留其他工作表、原单元格和空白行，部分完成及失败行也记录已知 ID 和原因。浏览器上传不会授予覆盖原本地文件的权限，因此导出更新后的副本；窗口内提供“下载结果 Excel”可再次下载，结果文件也可重新上传。已存在的同名位置仍跳过创建，唯一匹配时可导出其已有位置 ID。

“自动添加 DSP 联盟位置”默认开启，开关记在当前浏览器。开启时先核对当前媒体、SDK 应用及 `appicdsp` 联盟，创建、结算、启用和同步成功后，按相同位置编号定位该应用的 DSP 联盟位置，加入新集成的默认渠道。集成方式优先使用候选支持的 `c2s`，否则只接受候选中唯一可选方式；已有绑定直接跳过。关联后重新读取核验，缺少或重复候选、归属不符及请求失败会标记部分完成并保留位置 ID。关闭后不查询或修改 SDK/DSP，仍回填位置 ID 并导出 Excel。跳过的既有 SSP 位置不自动补充 DSP 绑定。

批量上传在预览、批次开始和每条创建前都会查询当前应用的已有广告位，只要最终名称相同就跳过，即使已有广告位尚未完成结算配置、启用或同步，也不会重新创建或修改。结果会列出已有广告位 ID，方便核对中断后的配置；查询失败、返回异常或列表未读取完整时不执行创建。检查期间即锁定操作，避免重复点击启动多个批次。

SDK 配置总览布局仅在 `#/sdk/config/overview` 生效，活跃度配置作为应用信息区外的独立区域展示，保留原有输入、修改、取消及保存行为。关闭该开关会将原组件放回信息区，并恢复原有布局。

集成渠道控量展示在 `#/sdk/integration/overview` 新增“渠道控量”只读列，按渠道展示实际保存的 `request_limit_switch` 开关状态，不推断继承关系。未配置模组、未配置开关和读取失败分别标记，失败时可重试。每次查询、翻页或从详情返回会重新读取，最多同时发起 4 个请求；关闭功能会移除列并取消读取。

1.2.1 修复了控量列对页面组件名和内部引用的依赖，改为按集成表格的列定位，并直接监听 VXE 表格的数据和加载状态。根 Vue 组件树未包含实际表格时，会继续从页面元素查找。当前运行版本可在设置页底部查看，或在控制台读取 `window.__apicmobCmsExtensionsVersion`。

集成详情添加渠道模组时，默认名称使用 `广告位名称_广告位ID_渠道名`，无定向渠道使用“默认渠道”，例如 `test_1792704791349911_默认渠道`。名称仍可手动修改，脚本不自动提交创建操作。

关闭开关会移除该功能的入口；已经开始的模组重建或广告位批量创建会继续完成，避免中断后留下不完整配置。已执行操作的结果和失败时的备份下载入口会保留到手动关闭。模组迁移的待处理数据和结果报告会保留，迁移完成后仍需核对并手动保存。

## 开发

```sh
npm run build
npm run check
npm test
```

根目录只保留一个可安装脚本 `cms-extensions.user.js`。各功能的源码位于 `src/features/`，由整合版统一启动；`src/cms-extensions.js` 管理设置、入口和统一页面监听。修改源码后运行构建，生成无需外部依赖的单文件安装包。

发布更新时，先提高 `scripts/build.js` 中的 `@version`，同步 `package.json` 和 `src/cms-extensions.js` 中的展示版本，再运行上述构建与检查。将源码和生成的 `cms-extensions.user.js` 一起提交并推送到 `origin/master`。Tampermonkey 通过版本号判断更新，仅推送代码而不提高版本号不会触发正常的版本更新。

`cms-extensions-settings.html` 可以直接打开预览设置界面。本地文件预览的存储与实际 CMS 站点隔离，预览中的开关不会修改 CMS 的设置。
